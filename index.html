        CrohnSight

        Image classification · severity grading

        0.992AUROC, lesion vs normal (CrohnIPI)
        Stack
        • PyTorch
        • EfficientNet-B2
        • ONNX Runtime
        • FastAPI
        • Next.js
        • Docker
        Authors
        With Hil Kalathiya and Chetan Gadhiya · PDEU minor project, guided by Prof. Dr. Babalu Kumar Singh
        Problem
        Reading a capsule-endoscopy study means checking tens of thousands of small-bowel frames by eye. Crohn's lesions are small and easy to miss.
        Approach
        An ensemble of 10 EfficientNet-B2 models (5 folds × 2 seeds) at the native 320 px finds lesions in 7 classes, grades severity in 4 tiers and draws a heat-map over each lesion. It is exported to ONNX and runs offline on an ordinary CPU. Add-ons cover ulcerative-colitis Mayo grading and flare-risk forecasting.
        Evaluation
        • Lesion vs normal accuracy96.7% (best published 94.6%)
        • Severity, quadratic weighted κ0.94
        • External test, Kvasir-CapsuleAUROC 0.944, no retraining
        Limits
        Research prototype, not a medical device. Telling a whole lesion video from a lesion-free one is near chance (study AUROC 0.57). The README reports this openly.

        Model card · 04 / 08

        Continual-learning research2026Public on GitHub

        Sleep-Consolidating LLM

        Memory consolidation · QLoRA · catastrophic forgetting

        0.325recall of earlier days' facts after 5 nights, no notebook (naive training: 0.035)
        Stack
        • PyTorch
        • Qwen2.5-0.5B
        • QLoRA (NF4)
        • PEFT
        • bitsandbytes
        • Transformers
        • pytest
        Authors
        Solo project
        Problem
        A language model learns nothing from what happens after training. An agent can keep notes, but the model itself either never absorbs them or, once fine-tuned on them, forgets older skills. Can it "sleep": turn a day's notes into weights without losing what it already knew?
        Approach
        Each simulated day a 4-bit Qwen2.5-0.5B-Instruct reads documents from a seeded synthetic world of names it cannot know (about 20% of facts are later updated) and writes atomic notes. At night it dreams: grounded question-answer pairs (answer-first), paraphrases and counterfactuals, de-duplicated and selected for diversity. One rank-16 QLoRA adapter is trained on a mix of 40% dreams from earlier nights, 20% ARC-Easy, HellaSwag and GSM8K train items and 40% new dreams, with a KL-to-base penalty on the replay part. QA is scored on held-out phrasings with no notebook.
        Evaluation
        • Today's facts, held-out phrasings0.38 (naive 0.11), mean of 3 seeds
        • Old-skill probe (ARC-Easy, HellaSwag, GSM8K)0.475 (base model 0.460, naive 0.392)
        • WikiText-2 perplexity39.6 (base model 26.6, naive 44.2)
        • Hardware4 GB laptop GPU (RTX 3050), 4-bit base model
        Limits
        Indicative only: 3 seeds, 5 nights, a 0.5B model and roughly 50 to 100 questions per cell. Training on dreams at all raises perplexity above the base model. Whether one rank-16 adapter holds about 1,500 facts is untested; a 30-night run is in progress. The earlier replay design forgot most earlier days (0.07 at day 5).

        Model card · 05 / 08

        Kaggle competition · quantum compilation2026Kaggle competition

        Verifiable Quantum Circuit Compilation

        Circuit optimisation · exact verification

        6.43×lower cost on invsqrt, own circuit (2,076,774 → 323,146)
        Stack
        • Python
        • kickmix
        • Qualtran
        • NumPy
        • GF(2^12) tower fields
        • Kaggle
        Authors
        Solo entry · public work of other participants credited
        Problem
        Fault-tolerant quantum algorithms are priced in qubits and Toffoli gates. Google Quantum AI's Kaggle competition asks for smaller circuits for three workloads: a 1/√x phase for fusion energy, a Reed-Solomon decoder for optimisation and FeMoCo chemistry loaders. An official verifier checks every submission on fresh random inputs, and the score is the geometric mean of the three cost reductions.
        Approach
        Own circuits for two of the three tasks, built with kickmix and checked with the official verifier logic. invsqrt: a table-based piecewise-quadratic design (192-entry QROM, binary shift count, barrel normaliser), lazy register allocation, narrow-window multiplies, measurement-based lookup erase and dead-gate removal checked over all 3.13M inputs. dqi: a tower-field GF(2^12) inverse (315 to 91 Toffolis), a 54-AND multiplier and a statistical dead-gate remover. Multi-core verifier runners for Windows run the full checks.
        Evaluation
        • invsqrt, own v6136 qubits, 2,125 Toffolis; full 64-shot check on all 3.13M inputs passed
        • dqi, own v51.64× (1,869 qubits; about 30 failures in 102,400 shots, R 1.276)
        • Own compositeabout 2.2 (6.43 × 1.64 × 1.0 for chemistry); not submitted
        • Own package scored on Kaggle1.628 (invsqrt v2 only), as predicted locally
        Limits
        The leaderboard's top scores come from public circuits of other participants. Re-verifying and submitting one such public stack scored 33.17 on Kaggle, but that is their work, credited in the repo, not mine. My own circuits reach about 2.2 and the chemistry task is untouched (1.0×). The dqi figure depends on a few decoder failures that vary with the grader's random draw. The code is not public.

        Model card · 06 / 08

        Kaggle competition · program synthesis2026Kaggle competition

        Santa 2026: Elf Calculator

        Shortest arithmetic programs · combinatorial search

        128,494total instructions after merging public programs (sample: 1,490,379)
        Stack
        • Python
        • C++
        • NumPy
        • pytest
        • Kaggle
        Authors
        Solo entry · public programs of other participants credited
        Problem
        For each of 1,000 puzzles a calculator with 48 registers starts from a few numbers and must produce every one of several huge targets (up to about 10^18) using + − × and exact division. The score is the total number of instructions across all puzzles, lower is better. The sample submission needs 1,490,379.
        Approach
        An exact referee re-implements the rules and replays every program. A Horner-style solver gives the baseline. A forward/backward dictionary beam search (meet-in-the-middle over 2 to 4M values), a value-DAG local search with register allocation and a C++ cone re-synthesiser then look for shorter programs, and a best-of merger replays banks of programs and keeps the shortest valid one per puzzle. A gap report shows about 80% of instructions build helper values and targets are mostly helper-op-helper.
        Evaluation
        • Own Horner baseline629,025 (−58% vs the sample)
        • Merged with public program banks133,610, then 128,494 with newer public outputs
        • Own search after the baseline0 instructions saved (beam, DAG search, cone re-synthesis up to 4 helpers)
        • Trivial lower bound26,898
        Limits
        Nearly all of the gain over my own baseline comes from other participants' public programs, replayed through the exact referee and credited in the repo; my beam search, local search and cone re-synthesis found nothing shorter than the public frontier. The code is in a private repository.

        Problem

        vMix Manager

        Batch automation · XML manipulation

        XMLedits .vmix session files directly, no running vMix needed
        Stack
        • Python
        • PyQt6
        • XML
        • PyInstaller
        • vMix 24+
        Authors
        Solo product
        Problem
        Large live shows have hundreds of playback files, and vMix's own interface means dragging them in one by one, renaming categories by hand and fixing broken paths input by input, hours before going on air.
        Approach
        Instead of controlling vMix through its API, it edits the .vmix session file's XML directly, so nothing needs to be open.         Features

        • Folder import with an automatic 214 px bold GT Title divider per folder
        • Category deep swap across vMix slots 1 to 6 and custom slots 50 to 65
        • Relink root: batch-update file paths when a project moves drive, with found/missing checks
        • Factory export, three wipe levels, drag-and-drop reorder and a timestamped activity log
        • One-file Windows executable through PyInstaller
        Specs
        • InterfacePyQt6, high-contrast black and white with Cambria type for stressful shows
        • Batch importmany folders queued, one GT Title header injected per folder
        • Category swaprewrites each input's category and keeps its position order
        • Safetyfresh UUID per cloned input; the README says to back up .vmix files first
        Limits
        An independent tool, not affiliated with or endorsed by StudioCoast (vMix). It rewrites session files directly, so a backup before any bulk operation is essential. Built for Windows and vMix 24 or newer.

        Product card · 03 / 03

        Local network security tool2026Public on GitHub

        SentinelProxy Suite

        DNS filtering · HTTPS proxy · live dashboard

        53 + 5309DNS and HTTPS-proxy ports served by one process
        Stack
        • Node.js
        • dns2
        • http-proxy
        • SQLite3
        • Express
        • socket.io
        • node-forge
        Authors
        Solo product
        Problem
        Ad and tracker blocking usually lives in a browser extension that malware and other apps can bypass, and DNS filters rarely show you what is happening live. A machine needs one place that blocks bad domains before a connection starts and cuts the network if that guard is bypassed.
        Approach
        A single Node.js process runs a DNS server on port 53 and an HTTPS proxy on port 5309. Queries are checked against blocklists indexed in SQLite3 and against heuristics (suspicious TLDs such as .zip, .mov, .top and .xyz, and tracker words like ads, track and pixel) before they resolve. It rewrites the system DNS and proxy settings and restores them on shutdown, generates its own certificates for HTTPS inspection, streams every query to a live dashboard over socket.io, and a Windows Firewall kill switch drops outgoing traffic if the proxy goes offline.
        Features
        • DNS server and HTTPS proxy in one process, with automatic system hooks and restore
        • Indexed SQLite3 blocklists plus heuristic pattern blocking
        • Certificate authority engine (node-forge) for local HTTPS inspection
        • Live HTTPS dashboard over Express and WebSockets with a query log you can export
        • Network kill switch through Windows Firewall rules
        • Standalone x64 executable built with pkg
        Specs
        • Blocklistsmillions of domains held in an indexed SQLite3 lookup (design target in the README)
        • Heuristicssuspicious TLDs and tracker substrings blocked before a name resolves
        • Dashboardlive query log over WebSockets, 12 screenshots in the repo
        • Packagingone portable x64 .exe; MIT licence
        Limits
        Windows-first: the kill switch and the system hooks use netsh and need an Administrator shell. Inspecting HTTPS means installing its own local certificate authority, so it is meant for machines you own. The README gives no benchmark of lookup speed.
